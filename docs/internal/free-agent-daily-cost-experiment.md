# Free Agent daily serving-cost allowance

[HAC-141](https://linear.app/hackerai/issue/HAC-141/experiment-free-agent-dollar010-daily-cost-allowance-versus-request) owns the hypothesis, rollout, guardrails, review date and cleanup decision. This is separate from the Free Agent model experiment, HAC-137.

`free_agent_daily_cost_v1` is evaluated on the server for authenticated Free Agent only. Control preserves the existing regional/default request and monthly policy. Test replaces Agent request counting and monthly admission with $0.10 of total serving cost per UTC day. Authorization, sandbox eligibility and free concurrency still apply. Ask keeps its existing request/monthly policy. All treatment spend remains in the monthly ledger for Ask and rollback.

The quota subject remains the existing identity-scoped shared key; PostHog assignment uses the authenticated user ID. A run freezes its UTC day when it reaches the quota check. Completed steps settle cumulative model/tool/compute cost, and settlement is atomic and idempotent across the daily ledger, monthly shadow ledger and per-attempt checkpoint. Settlement before a durable approval wait allows another run to use only the remaining allowance. Resume reacquires the lock and refreshes the monitor's capacity, adding back this run's already-settled cost because the monitor subtracts cumulative run cost. A run waiting past midnight must start a new request; late settlement still charges the original day. Provider steps and unreported work can overshoot the allowance; this is a mid-stream cost cutoff, not a prepaid reservation for an entire response.

`free_agent_budget_experiment_exposed` marks the eligible quota decision before enforcement, including requests denied by existing limits. It supplies `$feature/free_agent_daily_cost_v1` and experiment key/variant on that event. Cost and outcome events use `free_agent_budget_experiment_key` and `free_agent_budget_experiment_variant`, preserving the separate model experiment's generic attribution. No user content is recorded. Read both budget arms within each model arm and record the new phase boundary in HAC-137.

Production's primary is positive-payment `subscription_started`, `conversion_type=free_to_paid`, `invoice_amount_paid_dollars > 0`, within seven days of first exposure. The UI may include immature users; readouts must restrict to complete seven-day cohorts. Preview has cost and completed-response metrics but no payment primary until its real payment event is ingested. Successful response is activation evidence; natural completion needs the separate Agent outcome predicate and does not prove task success.

Deploy Vercel and Trigger separately. Preview uses PostHog 401167 and the designated HackerAI Developer Convex environment; Production uses PostHog 144137 and the designated HackerAI Convex environment. Verify the actual worker project-key fingerprint, Convex account/deployment, and user-facing URL before enabling either environment. No Convex schema change is needed. Once deployed, a flag change affects new Agent attempts without another deployment; existing attempts retain their selected policy. Disable the flag to restore baseline gates for new requests.

Acceptance on the real Preview URL requires a disposable account with verified Free entitlement and a connected local/desktop sandbox. In both arms, submit a bounded tool request, verify completion and reload the response. In test, verify Agent still starts after the existing request or monthly counter is exhausted, charges actual serving cost to the daily ledger, stops at the cost cap, shows the daily reset, and denies another attempt until reset. Verify approval/resume with another intervening run, cancellation, flag-off recovery, unchanged Ask/paid behavior, and both exposure and outcome/cost attribution. Record missing or blocked evidence explicitly before a Production ramp.
